# Gifski 视频转 GIF 文字编辑开发方案

日期：2026-09-13。基于上游提交 `e184b284886929b9401e2442629a57650d3231f4` 的源码检查；尚未编译或进行实现验证。工作量为工程估算。

## 1. 本期范围

- 视频导入后，在编辑页面增加文字层，导出的 GIF 包含文字。
- 支持添加、选择、删除多个文字框；每框支持多行文字。
- 调整位置、字号、系统字体、字体实际提供的样式/字重、填充颜色、描边颜色和粗细、段落对齐。
- 优先保证简体中文输入、中文标点换行、中文字体选择和中英文混排。
- 文字在整段输出动画中持续显示；现有裁剪、缩放、速度、循环和 bounce 继续工作。
- 不做 GIF 导入、字幕时间线、文字动画、自动字幕、字体文件管理、目标体积自动压缩或完整工程文件保存。
- 本期不增加文字旋转、渐变、阴影和逐字符富文本。样式指整框字体样式、字重、颜色、对齐及描边。

## 2. 源码事实与接入点

- `Gifski/EditScreen.swift`：编辑器状态、裁剪 overlay、设置变化调度、转换参数创建。
- `Gifski/Components/TrimmingAVPlayer.swift`：现有 NSView overlay 按实际视频区域布局，并处理裁剪控件与时间段选择器的事件穿透。
- `Gifski/GIFGenerator.swift`：通过 AVAssetReaderVideoCompositionOutput 完成方向、裁剪和缩放，转为 CGImage 后调用 addFrame；Conversion 当前没有文字字段。
- `Gifski/Preview/FullPreviewStream.swift`：完整预览复用 GIFGenerator；适合让文字自动进入实际编码预览。
- `Gifski/Preview/SettingsForFullPreview.swift`：转换参数快照、Sendable 传递、预览缓存相等性和复用判断，必须包含文字参数。
- `Gifski/EstimatedFileSize.swift`：使用 GIFGenerator 采样估算，应同样包含文字。
- `Gifski/AppState.swift`：现有 normal / preview / editCrop 模式，可增加 editText。
- `Gifski/ExportModifiedVideo.swift`：已有另一条视频导出路径，必须明确本期的产品行为，避免默默丢失文字。

## 3. 交互设计

编辑器工具栏增加“文字”，进入文字编辑模式。画面上显示选中文字框和拖动区域，属性面板显示文字内容、字体、样式、字号、填充及描边、对齐和位置。

支持多个文字框，按创建顺序叠放，新建位于最上层；通过列表选择重叠文字。第一期不做自由层级重排。新建默认白字黑边、底部居中，并选取可用的系统中文字体；默认值在原型中按实际小尺寸输出验证。

文字内容通过原生文本编辑控件输入，画面负责拖动和预览；不在第一期实现画布内光标编辑。字号可数值输入和滑块调整；文字框宽度通过拖动边缘控制自动换行。中文输入组合阶段不替换输入控件内容，也不启动完整编码。

“完成”提交当前文字编辑会话，“取消”恢复进入会话时的快照。会话内部支持撤销/重做：一次拖动或一次连续滑块操作合并为一条撤销记录；正常输入沿用原生文本撤销。退出文字编辑后，普通预览仍显示文字。裁剪模式与文字编辑模式互斥，进入裁剪时暂时隐藏文字，完成后按新输出画布重新布局。

## 4. 模型与坐标约定

新增 TextOverlay 为纯值模型，包含：id、text、fontPostScriptName、normalizedCenter、normalizedBoxWidth、normalizedFontSize、normalizedStrokeWidth、fillRGBA、strokeRGBA、alignment。数组顺序即叠放顺序。使用明确的 Equatable / Hashable / Sendable / Codable 实现，避免在跨 actor 参数中传 NSFont、NSColor、视图或可变 attributed string。

字体实际样式由具体 face 的 PostScript 名表示；字体家族与 face 列表是 UI 数据，不必重复持久化互相冲突的字重字段。系统不存在的样式不提供虚假开关。加载时字体不可用则回退并提示。

统一坐标系为最终裁剪后输出画布，左上角原点：位置和文本框宽度使用画布比例，字号和描边使用画布高度比例。面板显示当前输出像素尺寸对应的字号/描边数值；输出尺寸改变时比例保持不变，因此文字随 GIF 整体缩放。

普通视频预览仍可能显示未裁剪的源画面，必须将文字从输出画布映射到实际视频区域中的 crop rect。编码预览显示最终裁剪结果，按完整输出画布布局。不得使用窗口尺寸直接计算文字位置，也不能把 Retina backing scale 当成输出尺寸。

框高由文字排版计算；在描边范围外增加安全边距。位置拖动限制使用包含描边的实际可见边界；文字过大超过画布时显示越界提示，不能静默缩小用户字号。编码阶段统一裁切到输出画布。

## 5. 共用文字渲染模块

新增 TextOverlayRenderer，使用 Core Text / Core Graphics 排版和绘制，生成最终输出分辨率下的透明文字图层，并返回各框的命中测试边界。

建议先绘制轮廓再绘制填充，避免粗描边挤占中文字内部。Core Text stroke 属性和两次绘制方案在原型阶段比较；产品中的描边单位为输出像素，不直接暴露 Apple 按字号百分比定义的 strokeWidth。

排版、换行和实际字形由系统文字引擎处理。面板原生控件负责输入，画面预览使用 renderer 生成的图像，不用另一套 SwiftUI Text 排版模拟最终效果。字体列表提供中文示例及当前文本预览；允许系统缺字回退，但对所选字体不覆盖文字的情况给出轻量提示。

每个导出/估算任务持有自己的不可变文字快照；在任务内部创建渲染资源。静态文字按“文字参数＋输出尺寸”生成一次并复用，视频每帧只做合成。避免全局无限缓存，也不缓存所有视频帧。

## 6. GIF 导出与预览集成

在 Conversion 中新增 textOverlays，默认为空。GIFGenerator 在方向、裁剪、缩放完成后，进入正向/bounce 两次 addFrame 之前合成文字。正反向复用合成后的同一帧。不要只修改 convertOneFrame：完整 GIF 导出并不依靠它逐帧执行。

无文字或仅空字符串时直接沿用旧路径，不增加绘制和像素复制。保留源帧 alpha；明确文字图层与源帧颜色空间、预乘 alpha 和上下翻转约定。

编辑模式使用轻量 overlay，即时渲染当前文字；不对每个拖动采样做 GIF 编码。松手、结束字号滑块操作或完成输入后，复用现有防抖/取消机制刷新完整预览和文件大小估算。输入法仍有 marked text 时推迟后台任务。

完整预览参数快照、相等性、toConversion 等往返转换均加入文字字段。完整预览已经包含文字，不能再绘制一次轻量文字 overlay；模式切换时根据请求版本清理旧预览，防止双重文字或旧结果覆盖。

UI 主线程仅处理输入、选择、轻量布局与结果展示；编码和后台渲染不阻塞主线程。先保证缓存复用及正确取消，再根据性能测量决定是否进一步优化。

## 7. 视频导出与设置保存

本期文字仅承诺输出到 GIF。存在非空文字时，暂时禁用现有“导出修改后视频”入口，并在入口附近明确说明“含文字的视频导出暂未支持”。无文字时保持原有行为。未来可以接入共用渲染器支持视频输出。

保存最近字体、字号比例、颜色和描边等样式偏好；不要把上一段视频的文字内容自动带入下一段视频。文字模型属于当前编辑会话，不放入全局 Defaults。暂不创建可重新打开的项目文件。

## 9. 实现顺序和阶段验收

### A. 构建基线与渲染探针：1—2 个工作日

确认目标 macOS/Xcode 版本，使用独立应用标识和签名设置构建 fork，运行现有相关测试。固定一段视频和中文文本，完成带描边文字的单帧合成及 GIF 导出，检查方向、字形、透明度、循环与性能。此阶段确认 API 和构建可行性，再推进 UI。

### B. 单文字框端到端：3—5 个工作日

实现值模型、共用 renderer、系统字体及 face 选择、字号填充/描边设置、位置和换行框调整。先贯通单框输入到导出，并让普通播放显示文字。验收：中文字体切换可见、描边可控、导出位置准确。

### C. 完整编辑体验：3—5 个工作日

加入多框、选择/删除、会话完成/取消、撤销、最近样式，以及裁剪后坐标映射；接入完整 GIF 预览、缓存失效和估算。防止文字重复合成、输入法中断和过时任务回写。明确视频导出限制。

### D. 回归与打磨：3—5 个工作日

完成中文和几何验收、性能及大视频验证，修复导出一致性问题，准备本地可安装构建。

合计估计 10—17 个熟练开发者工作日，按约 2—4 周安排；不含兼容旧 macOS、复杂字体特效或发布平台审核。先在 A 阶段结束后依据实测修订工期。

## 10. 验收矩阵

- 中文：简体中文、全角标点、中英文数字混排、多行、连续输入法组合、长文本；验证至少两款系统中实际可用的中文字体及其字重。
- 描边：关闭、细、粗描边，颜色修改；小尺寸 GIF 中无被切断轮廓或异常黑边。
- 几何：横屏、竖屏、带旋转信息视频；裁剪后、缩放后、窗口大小和 Retina 缩放变化；框位置和字形比例与最终输出一致。
- 多框：重叠、删除、撤销、空字符串、超长文字；创建/取消/重新打开视频不会泄漏状态。
- 输出：不同质量/FPS、截取区间、变速、循环和 bounce；完整预览和解码后的 GIF 帧均包含正确文字。量化允许颜色差异，位置/布局必须一致。
- 性能：拖动与输入期间不启动完整编码；后台工作可取消，旧请求不能覆盖新状态；静态文字不逐帧重新排版；不随视频帧数无限增长内存。
- 回归：无文字时仍走原路径；已有裁剪、透明视频、预览、估算、GIF 导出和无文字视频导出继续通过相关测试。

自动化重点：坐标/字号转换、文字模型快照往返及缓存失效、合成后的帧边界和 alpha、空文字直通路径、端到端 GIF 时长/循环。字体截图只在固定字体与系统环境中比较，避免跨系统依赖逐像素完全相等。

## 11. 开工前的唯一环境决策

当前上游面向 macOS 26+，部分 target 设置不同。先确认实际运行系统、可用 Xcode SDK 和各 target 构建要求；若需要更旧系统兼容，另行评估基线，不把回移植混入文字功能开发。
